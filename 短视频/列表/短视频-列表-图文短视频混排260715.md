# 短视频-列表-图文短视频混排260715

## 一、需求背景

### 1.1 现状与问题

当前动态页存在「小视频」和「广场」两个 tab，分别采用全屏沉浸样式和信息流卡片样式，同一动态业务两套样式、两套信息流逻辑，用户心智割裂。两个 tab 需分别运营内容池与推荐策略，人力与配置成本翻倍，优质内容难以跨 tab 复用曝光。

本次需求将图文类动态适配进全屏沉浸信息流并与短视频混排，下线广场 tab，统一内容分发入口，降低运营成本并提升沉浸消费体验。

**需求来源：** [需求文档：短视频-图文短视频混排260714](https://uf1iawhques.sg.larksuite.com/docx/H7o0deaR0oly2fx0xhllCDgIgZg)

### 1.2 目标

> **核心目标：** 将图文、纯图片、纯文本动态统一以全屏沉浸样式混入短视频信息流，下线广场 tab，实现一套信息流、一套推荐策略的统一分发，提升内容曝光效率与人均消费时长。

### 1.3 关键指标

| 指标 | 当前值 | 目标值 | 统计口径 |
|------|--------|--------|----------|
| 人均浏览时长 | — | +X% | BI |
| 图文类内容曝光量 | — | 新增 | BI |
| 图文类互动率（赞/评/分享） | — | 新增 | BI |
| 运营策略配置成本 | 两套 | 一套 | 运营反馈 |

## 二、需求说明

本期聚焦**客户端展示端统一**——将图文类动态适配进全屏沉浸信息流并与短视频混排、广场 tab 下线。发布端与运营后台暂维持现状，作为二期统一。

### 2.1 功能点 FUNC-001：动态页 Tab 导航重构

#### 功能描述

动态页顶部 tab 导航进行调整：移除「广场」tab，将原「小视频」tab 更名为「精选」，作为默认 tab。调整后 tab 顺序为：关注、精选、热门、创作者。通过服务端版本控制实现新老版本兼容——老版本继续展示广场 tab，新版本下线广场 tab。

#### 交互规则（每条标注处理端）

- **Tab 移除：** `[服务端]` 新版本客户端请求 tab 配置时，服务端不再下发「广场」tab；老版本客户端请求时仍正常下发「广场」tab
- **Tab 更名：** `[客户端]` 原「小视频」tab 展示文案改为「精选」，使用多语言 key `tab_shortvideo`（文案更新为"精选"）
- **Tab 顺序：** `[服务端]` tab 配置接口下发顺序为：关注、精选、热门、创作者
- **默认 Tab：** `[客户端]` 用户进入动态页时默认选中「精选」tab
- **版本控制：** `[服务端]` 通过客户端版本号判断是否下发广场 tab，版本阈值由服务端配置控制，支持灰度放量

#### 异常处理

- **数据为空：** `[客户端]` tab 配置接口返回空时，使用本地缓存的上一次 tab 配置兜底展示；若无缓存则展示默认 tab 列表（关注、精选、热门、创作者）
- **文本超长：** `[客户端]` tab 文案均为固定短文案（2-3字），不存在超长问题
- **网络异常：** `[客户端]` tab 配置请求失败时使用本地缓存兜底；若无缓存使用硬编码默认配置
- **重复操作：** `[客户端]` 快速连续切换 tab 时，取消前一次未完成的列表请求，仅执行最后一次切换对应的请求

### 2.2 功能点 FUNC-002：图文/纯图片动态卡

#### 功能描述

在全屏沉浸信息流中新增图文/纯图片类型动态卡。卡片沿用全屏沉浸卡骨架（右侧互动栏、底部作者+文案区、顶部 tab），主体区展示图片横向轮播。多图时底部居中显示页码指示条，支持自动轮播（每3秒切换）和手动左右滑动切换。用户昵称后标注"图文"类型标签。

#### 交互规则（每条标注处理端）

- **卡片骨架：** `[客户端]` 复用全屏沉浸卡骨架布局（右侧互动栏、底部作者+文案区、顶部 tab），主体区替换为图片轮播区域
- **类型标签：** `[客户端]` 在用户昵称后展示"图文"类型标签，区分内容形态
- **图片展示：** `[客户端]` 图片适配规则：竖图铺满屏幕宽度、横图/方图居中留白（具体裁切规则待设计确认）
- **页码指示条-显示条件：** `[客户端]` 图片总数≥2时，在轮播区域底部居中显示页码指示条；图片总数=1时不显示指示条
- **页码指示条-视觉规则：** `[客户端]` 当前展示图片及其左侧所有指示点为高亮样式（已访问），当前图片右侧所有指示点为置灰样式（未访问）
- **自动轮播：** `[客户端]` 每3秒自动切换至下一张图片，到达末张后循环至首张，无限播放
- **手动滑动：** `[客户端]` 用户左右滑动可手动切换图集内图片；手动滑动后停止自动轮播，不再恢复
- **指示条点击：** `[客户端]` 点击已访问状态的指示点，直接跳转展示对应图片；点击未访问状态的指示点，展示下一张图片；点击后停止自动轮播
- **底部文案：** `[客户端]` 正文在底部文案区展示，超长文本折叠并显示"展开"按钮
- **上下滑切换：** `[客户端]` 上下滑动切换信息流中的上/下一条动态，交互逻辑同现有短视频卡
- **互动操作：** `[客户端]` 点赞、评论、分享、关注等互动操作沿用现有短视频卡逻辑
- **数据来源：** `[服务端]` 列表接口下发内容类型标识（video/imagetext/image/text）及图片列表数据，客户端根据类型渲染对应卡片

#### 异常处理

- **数据为空：** `[客户端]` 图片列表为空时，该条动态跳过不渲染，避免展示空白卡片
- **文本超长：** `[客户端]` 底部文案区正文超出最大展示行数时折叠，显示"展开"按钮；用户昵称超长按固定宽度截断显示省略号
- **网络异常：** `[客户端]` 图片加载中显示占位/模糊预览图；图片加载失败时显示重试按钮，点击重试重新加载当前图片
- **重复操作：** `[客户端]` 快速连续左右滑动时做节流处理，避免图片切换过快导致卡顿；自动轮播与手动滑动互斥，手动操作立即中断自动轮播

### 2.3 功能点 FUNC-003：纯文本动态卡

#### 功能描述

在全屏沉浸信息流中新增纯文本类型动态卡。卡片沿用全屏沉浸卡骨架（右侧互动栏、底部作者+文案区、顶部 tab），主体区以品牌化背景 + 文本居中方式呈现。用户昵称后标注"文字"类型标签。正文同时在底部文案区重复展示，超长文本折叠。

#### 交互规则（每条标注处理端）

- **卡片骨架：** `[客户端]` 复用全屏沉浸卡骨架布局，主体区替换为品牌化背景 + 居中文本
- **品牌化背景：** `[客户端]` 主体区使用品牌化背景样式（具体背景图/渐变由设计稿确定），文本内容居中展示
- **类型标签：** `[客户端]` 在用户昵称后展示"文字"类型标签
- **文案展示：** `[客户端]` 正文在主体区居中展示的同时，在底部文案区重复展示；底部文案超长时折叠并显示"展开"按钮
- **上下滑切换：** `[客户端]` 上下滑动切换信息流中的上/下一条动态，交互逻辑同现有短视频卡
- **互动操作：** `[客户端]` 点赞、评论、分享、关注等互动操作沿用现有短视频卡逻辑
- **数据来源：** `[服务端]` 列表接口下发内容类型标识为 text，附带正文文本内容

#### 异常处理

- **数据为空：** `[客户端]` 正文内容为空时，该条动态跳过不渲染
- **文本超长：** `[客户端]` 主体区居中文本超出最大展示行数时截断显示省略号；底部文案区超长时折叠显示"展开"按钮
- **网络异常：** `[客户端]` 品牌化背景资源加载失败时使用本地默认纯色背景兜底，不影响文本展示
- **重复操作：** `[客户端]` 上下滑切换做防抖处理，快速连续滑动时取消中间态渲染，仅渲染最终停留的动态卡

### 2.4 功能点 FUNC-004：我的页面 - 详情页适配

#### 功能描述

用户从「我的页面」点击图文或纯文本动态进入详情页时，详情页沿用对应的全屏沉浸卡样式。图文详情页展示图片横向轮播 + 页码指示条 + 底部作者/文案区 + 右侧互动栏；文本详情页展示品牌化背景 + 文本居中 + 底部文案区 + 右侧互动栏。主态下保留管理入口（编辑/删除等），支持上下滑切换本人动态列表内的上/下一条。

#### 交互规则（每条标注处理端）

- **图文详情页（主态）：** `[客户端]` 从「我的页面」点击图文动态进入，沿用全屏沉浸图文卡样式（图片横向轮播 + 页码指示条 + 底部作者/文案区 + 右侧互动栏），昵称后标注"图文"类型标签
- **文本详情页（主态）：** `[客户端]` 从「我的页面」点击纯文本动态进入，沿用全屏沉浸文本卡样式（品牌化背景 + 文本居中 + 底部文案区 + 右侧互动栏），昵称后标注"文字"类型标签
- **管理入口：** `[客户端]` 主态下的管理入口（编辑/删除等）沿用现有逻辑，位置和交互不变
- **上下滑切换：** `[客户端]` 上下滑动切换本人动态列表内的上/下一条动态
- **图文轮播交互：** `[客户端]` 图文详情页的左右滑切换图片、页码指示条交互逻辑同 FUNC-002
- **客态展示：** `[客户端]` 他人主页点击图文/文本动态进入详情页时，展示逻辑同主态，但不展示管理入口
- **数据来源：** `[服务端]` 详情页数据复用列表接口已下发的动态数据，无需额外请求；上下滑切换时按本人动态列表顺序加载

#### 异常处理

- **数据为空：** `[客户端]` 动态已被删除或不可见时，展示"该动态已删除"提示，支持返回上一页
- **文本超长：** `[客户端]` 底部文案区超长文本折叠显示"展开"按钮，规则同 FUNC-002/FUNC-003
- **网络异常：** `[客户端]` 详情页加载失败时展示通用错误页，支持点击重试
- **重复操作：** `[客户端]` 管理操作（删除等）做防重处理，操作中禁用按钮，避免重复提交

### 2.5 功能点 FUNC-005：混排推荐策略

#### 功能描述

「精选」tab 信息流的所有内容（短视频 + 图文 + 纯图片 + 纯文本）全部由推荐引擎统一召回、排序、下发。图文/图片/文本作为新内容类型接入现有短视频推荐链路，与短视频进入同一内容池同池竞争曝光。整体配比以短视频为主、图文类为辅，保持沉浸消费的主心智不变。

#### 交互规则（每条标注处理端）

- **统一分发：** `[服务端]` 精选 tab 信息流不设人工插入位、不做形态固定坑位，混排顺序完全由推荐算法决定
- **同池竞争：** `[服务端]` 图文/图片/文本与短视频进入同一推荐内容池，由推荐算法综合内容质量、用户兴趣、时效、互动预估等因子统一排序
- **形态配比：** `[服务端]` 短视频占比高于图文类，通过推荐侧的形态权重/配额策略实现（如按滑动窗口控制图文类占比上限），初期建议值待与推荐确认
- **冷启探索：** `[服务端]` 推荐侧对图文类做冷启探索与兴趣召回，逐步校准图文与短视频的分发比例
- **兜底策略：** `[服务端]` 推荐内容不足时回捞兜底内容补位，保证信息流不断流
- **客户端渲染：** `[客户端]` 严格按服务端返回顺序渲染，不做二次排序；根据每条内容的类型标识渲染对应卡片样式

#### 异常处理

- **数据为空：** `[客户端]` 信息流整体无数据时展示空状态占位图与提示文案；加载更多返回空时展示"没有更多内容了"
- **文本超长：** 不涉及（本功能点为策略逻辑，无文本展示）
- **网络异常：** `[客户端]` 列表请求失败时展示失败提示与"点击重试"；`[服务端]` 单条内容加载失败时跳过并上报，不阻塞滑动与后续下发
- **重复操作：** `[客户端]` 下拉刷新/加载更多做防重处理，加载中不重复触发请求

### 2.6 功能点 FUNC-006：热门 Tab 全面开放与 Banner 配置

#### 功能描述

将热门 tab 新样式从当前灰度地区（菲律宾、尼泊尔）全面开放至所有国家/地区。同时在短视频热门页顶部新增 banner 广告位，支持运营后台配置。

#### 交互规则（每条标注处理端）

- **全面开放：** `[服务端]` 热门 tab 新样式取消地区限制，对所有国家/地区的新版本客户端统一下发新样式配置
- **老样式下线：** `[服务端]` 原老样式地区（印尼、马来、印度、孟加拉、沙特、巴基斯坦）升级为新样式
- **版本兼容：** `[服务端]` 老版本客户端（poppo android<539、ios<451）继续展示老样式；新版本统一展示新样式
- **vone 适配：** `[客户端+服务端]` vone 端热门 tab 展示策略待确认（当前不展示）
- **Banner 广告位：** `[客户端]` 短视频热门页顶部展示 banner 广告位，位置在 tab 导航下方、内容列表上方
- **Banner 数据：** `[服务端]` banner 内容由运营后台配置下发，支持图片+跳转链接
- **Banner 尺寸：** `[客户端]` 具体尺寸待设计确认

#### 异常处理

- **数据为空：** `[客户端]` banner 配置为空或未下发时，不展示 banner 区域，内容列表顶部对齐 tab 导航
- **文本超长：** 不涉及（banner 为图片形式，无文本溢出问题）
- **网络异常：** `[客户端]` banner 图片加载失败时隐藏 banner 区域，不展示占位；热门列表请求失败时展示通用失败提示与重试
- **重复操作：** `[客户端]` banner 点击跳转做防抖处理，避免连续点击打开多个页面
