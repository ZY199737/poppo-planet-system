# 荣誉消息通知 & 荣誉分享 — 复盘数据表设计

## 一、表总览

| 表名 | 用途 | 类型 |
|------|------|------|
| `honor_notification_event` | 荣誉通知触发与送达事件 | 事实表（明细） |
| `honor_poster_action` | 海报/卡片互动行为 | 事实表（明细） |
| `honor_share_tracking` | 分享渠道追踪 | 事实表（明细） |
| `honor_invite_conversion` | 分享回流与邀请转化 | 事实表（明细） |
| `honor_daily_stats` | 日维度汇总统计 | 聚合表 |
| `honor_type_config` | 荣誉类型配置（维度表） | 维度表 |

---

## 二、表结构

### 1. `honor_type_config` — 荣誉类型配置表

维度表，枚举所有荣誉类型及其层级，供其他表关联。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INT, PK, AUTO_INCREMENT | 主键 |
| `honor_category` | VARCHAR(32) | 荣誉大类：`medal`(勋章荣誉) / `host_level`(主播等级荣誉) / `user_honor`(用户荣誉) |
| `honor_type` | VARCHAR(64) | 荣誉小类：`live_star` / `random_pk` / `intimacy` / `active_star` / `hourly_host_upgrade` / `hourly_host_weekly` / `svip` / `king_guardian` |
| `honor_name` | VARCHAR(128) | 荣誉展示名称，如 "直播之星"、"随机PK胜利者" |
| `level_min` | INT | 该类型最低触发等级（如直播之星为3） |
| `level_max` | INT | 该类型最高触发等级（如直播之星为10） |
| `has_level` | TINYINT(1) | 是否有等级概念（SVIP/王者守护为0，勋章类为1） |
| `template_title_key` | VARCHAR(128) | 消息模版标题 key |
| `template_text_key` | VARCHAR(128) | 消息模版文案 key |
| `created_at` | DATETIME | 创建时间 |

---

### 2. `honor_notification_event` — 荣誉通知触发与送达事件表

记录每一条荣誉通知从触发到送达、打开的全链路状态。**全链路漏斗的核心表。**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT, PK, AUTO_INCREMENT | 主键 |
| `event_id` | VARCHAR(64), UNIQUE | 事件唯一标识（去重用） |
| `user_id` | BIGINT, INDEX | 接收通知的用户 UID |
| `user_role` | VARCHAR(16) | 用户身份：`host`(主播) / `viewer`(观众) / `both` |
| `honor_type` | VARCHAR(64), INDEX | 荣誉小类（关联 honor_type_config.honor_type） |
| `honor_category` | VARCHAR(32), INDEX | 荣誉大类 |
| `honor_level` | INT | 触发的具体等级（无等级的填0） |
| `honor_extra_value` | DECIMAL(12,2) | 附加数值：时薪金额 / SVIP金币金额 / 守护金币金额（无则为0） |
| `trigger_time` | DATETIME, INDEX | 触发时间 |
| `is_delivered` | TINYINT(1), DEFAULT 0 | 是否成功送达（消息到达客户端） |
| `delivered_time` | DATETIME | 送达时间 |
| `is_opened` | TINYINT(1), DEFAULT 0 | 是否打开消息（用户点击消息列表） |
| `opened_time` | DATETIME | 打开时间 |
| `is_card_viewed` | TINYINT(1), DEFAULT 0 | 是否查看 H5 荣誉卡片 |
| `card_viewed_time` | DATETIME | 卡片查看时间 |
| `is_poster_generated` | TINYINT(1), DEFAULT 0 | 是否生成了海报（点击保存或分享时触发） |
| `poster_generated_time` | DATETIME | 海报生成时间 |
| `client_version` | VARCHAR(32) | 客户端版本号（用于区分新/老版本行为差异） |
| `platform` | VARCHAR(16) | 平台：`ios` / `android` |
| `created_at` | DATETIME | 记录创建时间 |
| `updated_at` | DATETIME | 记录更新时间 |

**索引建议：**
- `idx_user_time`: (`user_id`, `trigger_time`)
- `idx_type_time`: (`honor_type`, `trigger_time`)
- `idx_category_time`: (`honor_category`, `trigger_time`)

---

### 3. `honor_poster_action` — 海报互动行为表

记录用户在荣誉卡片页面的每一次操作（保存、分享）。一个通知事件可对应多条行为。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT, PK, AUTO_INCREMENT | 主键 |
| `event_id` | VARCHAR(64), INDEX | 关联 honor_notification_event.event_id |
| `user_id` | BIGINT, INDEX | 操作用户 UID |
| `honor_type` | VARCHAR(64), INDEX | 荣誉小类（冗余，便于直接按类型查询） |
| `honor_category` | VARCHAR(32) | 荣誉大类（冗余） |
| `honor_level` | INT | 触发等级 |
| `action_type` | VARCHAR(16) | 操作类型：`save`(保存到相册) / `share`(触发分享) |
| `action_time` | DATETIME, INDEX | 操作时间 |
| `platform` | VARCHAR(16) | 平台：`ios` / `android` |
| `client_version` | VARCHAR(32) | 客户端版本 |
| `created_at` | DATETIME | 记录创建时间 |

---

### 4. `honor_share_tracking` — 分享渠道追踪表

记录每次分享的渠道、类型和结果。粒度到单次分享行为。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT, PK, AUTO_INCREMENT | 主键 |
| `share_id` | VARCHAR(64), UNIQUE | 分享唯一标识 |
| `event_id` | VARCHAR(64), INDEX | 关联 honor_notification_event.event_id |
| `user_id` | BIGINT, INDEX | 分享用户 UID |
| `honor_type` | VARCHAR(64), INDEX | 荣誉小类 |
| `honor_category` | VARCHAR(32) | 荣誉大类 |
| `honor_level` | INT | 触发等级 |
| `share_scope` | VARCHAR(16) | 分享范围：`internal`(站内) / `external`(站外) |
| `share_channel` | VARCHAR(32) | 分享渠道：`in_app_chat`(站内聊天) / `facebook` / `x` / `whatsapp` / `instagram` / `telegram` / `line` / `other` |
| `share_time` | DATETIME, INDEX | 分享时间 |
| `share_result` | VARCHAR(16) | 分享结果：`success` / `cancel` / `fail` |
| `target_user_id` | BIGINT | 站内分享时的接收方 UID（站外为空） |
| `share_link` | VARCHAR(512) | 站外分享携带的链接（含邀请码） |
| `invite_code` | VARCHAR(64), INDEX | 分享链接中的邀请码（用于关联回流转化） |
| `platform` | VARCHAR(16) | 平台 |
| `created_at` | DATETIME | 记录创建时间 |

---

### 5. `honor_invite_conversion` — 分享回流与邀请转化表

追踪通过荣誉海报二维码/链接带来的新用户回流和邀请绑定。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT, PK, AUTO_INCREMENT | 主键 |
| `invite_code` | VARCHAR(64), INDEX | 邀请码（关联 honor_share_tracking.invite_code） |
| `share_id` | VARCHAR(64), INDEX | 关联 honor_share_tracking.share_id |
| `sharer_user_id` | BIGINT, INDEX | 分享者 UID |
| `new_user_id` | BIGINT, INDEX | 新用户 UID |
| `conversion_type` | VARCHAR(32) | 转化类型：`qr_scan`(扫码) / `link_click`(链接点击) |
| `source_channel` | VARCHAR(32) | 来源渠道（同 share_channel） |
| `honor_type` | VARCHAR(64) | 触发转化的荣誉类型 |
| `is_app_downloaded` | TINYINT(1), DEFAULT 0 | 是否下载了 APP |
| `is_registered` | TINYINT(1), DEFAULT 0 | 是否完成注册 |
| `is_invite_bindbound` | TINYINT(1), DEFAULT 0 | 是否成功建立邀请绑定关系 |
| `click_time` | DATETIME | 扫码/点击链接时间 |
| `download_time` | DATETIME | 下载时间 |
| `register_time` | DATETIME | 注册时间 |
| `bindbound_time` | DATETIME | 邀请绑定时间 |
| `created_at` | DATETIME | 记录创建时间 |
| `updated_at` | DATETIME | 记录更新时间 |

---

### 6. `honor_daily_stats` — 日维度汇总统计表

按天、按荣誉类型聚合核心指标，支持快速查询复盘看板。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT, PK, AUTO_INCREMENT | 主键 |
| `stat_date` | DATE, INDEX | 统计日期 |
| `honor_category` | VARCHAR(32) | 荣誉大类 |
| `honor_type` | VARCHAR(64) | 荣誉小类 |
| `honor_level` | INT | 等级（0表示全等级汇总） |
| `platform` | VARCHAR(16) | 平台（`all` 表示全平台汇总） |
| **— 全链路漏斗 —** | | |
| `trigger_count` | INT, DEFAULT 0 | 触发通知数 |
| `trigger_user_count` | INT, DEFAULT 0 | 触发通知用户数（去重） |
| `delivered_count` | INT, DEFAULT 0 | 送达数 |
| `delivered_rate` | DECIMAL(5,4) | 送达率 = delivered / trigger |
| `opened_count` | INT, DEFAULT 0 | 打开数 |
| `opened_rate` | DECIMAL(5,4) | 打开率 = opened / delivered |
| `card_viewed_count` | INT, DEFAULT 0 | 卡片查看数 |
| `card_viewed_rate` | DECIMAL(5,4) | 卡片查看率 = card_viewed / opened |
| `poster_generated_count` | INT, DEFAULT 0 | 海报生成数 |
| `poster_generated_rate` | DECIMAL(5,4) | 海报生成率 = poster_generated / card_viewed |
| **— 互动指标 —** | | |
| `save_count` | INT, DEFAULT 0 | 保存次数 |
| `save_user_count` | INT, DEFAULT 0 | 保存用户数 |
| `share_count` | INT, DEFAULT 0 | 分享次数 |
| `share_user_count` | INT, DEFAULT 0 | 分享用户数 |
| `share_success_count` | INT, DEFAULT 0 | 分享成功次数 |
| **— 分享渠道分布 —** | | |
| `internal_share_count` | INT, DEFAULT 0 | 站内分享次数 |
| `external_share_count` | INT, DEFAULT 0 | 站外分享次数 |
| `facebook_share_count` | INT, DEFAULT 0 | Facebook 分享次数 |
| `whatsapp_share_count` | INT, DEFAULT 0 | WhatsApp 分享次数 |
| `x_share_count` | INT, DEFAULT 0 | X(Twitter) 分享次数 |
| `other_share_count` | INT, DEFAULT 0 | 其他渠道分享次数 |
| **— 回流转化 —** | | |
| `link_click_count` | INT, DEFAULT 0 | 链接/二维码点击数 |
| `app_download_count` | INT, DEFAULT 0 | APP 下载数 |
| `register_count` | INT, DEFAULT 0 | 新用户注册数 |
| `invite_bindbound_count` | INT, DEFAULT 0 | 邀请绑定成功数 |
| `invite_conversion_rate` | DECIMAL(5,4) | 邀请转化率 = invite_bind / link_click |
| `created_at` | DATETIME | 记录创建时间 |
| `updated_at` | DATETIME | 记录更新时间 |

**唯一索引：** `uk_date_type`: (`stat_date`, `honor_type`, `honor_level`, `platform`)

## 三、核心复盘查询场景

### 场景 1：全链路漏斗（某日/某段时间）

```
触发 → 送达 → 打开 → 查看卡片 → 生成海报 → 保存/分享
```
查 `honor_daily_stats`，按 `stat_date` 筛选，看 `trigger → delivered → opened → card_viewed → poster_generated → (save + share)` 各环节转化率。

### 场景 2：各荣誉类型对比

查 `honor_daily_stats`，按 `honor_category` 或 `honor_type` 分组，对比：
- 哪类荣誉触发量最大？
- 哪类荣誉打开率最高？（用户对哪类荣誉最感兴趣）
- 哪类荣誉分享率最高？（哪类荣誉社交传播意愿最强）
- 哪类荣誉带来的回流新用户最多？

### 场景 3：分享渠道效果分析

查 `honor_daily_stats` 的渠道字段，或明细查 `honor_share_tracking`：
- 站内 vs 站外分享占比
- 各站外渠道（Facebook/WhatsApp/X）的分享量和成功率
- 各渠道带来的回流转化率

### 场景 4：新老版本对比

查 `honor_notification_event`，按 `client_version` 分组：
- 新版本用户的分享率 vs 老版本用户的保存率（老版本只有保存按钮）
- 新版本上线后，整体分享量的增长趋势

### 场景 5：邀请回流归因

查 `honor_invite_conversion` + `honor_share_tracking`：
- 单个荣誉海报能带来多少新用户？
- 从扫码/点击 → 下载 → 注册 → 绑定邀请关系，每步的流失率
- 哪类荣誉的海报拉新效果最好？

## 四、ER 关系

```
honor_type_config (1) ←──── (N) honor_notification_event
                                    │
                                    ├── (1:N) honor_poster_action
                                    │
                                    └── (1:N) honor_share_tracking
                                                    │
                                                    └── (1:N) honor_invite_conversion
```

- 一条通知事件 → 可触发多次海报操作（保存+分享）
- 一条通知事件 → 可产生多次分享（不同渠道）
- 一次分享 → 可带来多个回流用户
